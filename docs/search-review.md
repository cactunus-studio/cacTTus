# Разбор поиска TikTok 47.7.1

Исходный APK: `3b68b645a9d6ab69336152c613e644aaaf8d09aa001413518f27b4517be07b0c`.

| Участок | Что установлено | Изменение / ограничение |
|---|---|---|
| Видео и люди | Видео использует `SearchApiNew`, люди имеют отдельный вызов | Настройка клиента видео выполняется отдельно |
| Версия API | `X/0IkU` выбирает v1 или `/aweme/v2/search/general/...` | Политика охватывает обе версии |
| Создание клиента | Есть ветки с конвертером и через shortcut фабрики | Обработчик подключён в обеих ветках; конвертер сохраняется |
| Регион SIM | Подмена глобальна, оригинальное значение до неё было потеряно | Оригинал сохраняется в RAM; лента продолжает видеть выбранную страну |
| GET-параметры | В поисковом URL могут находиться SIM-поля | Меняются только уже существующие SIM-поля и `priority_region` на разрешённых API; остальные сырые байты сохраняются |
| Метод видео-запроса | `LX/05jU` в RequestFactory соответствует POST | Проверка только URL была неполной |
| POST-форма | SDK использует `X/07Hx`, списки имён/значений и обёртку `X/0OxD` | Новая форма строится из копий; изменяются только SIM-поля и `priority_region` |
| Два тела запроса | `Request.getBody()` предпочитает `requestBody`, даже если `body/TypedOutput` уже изменён | Исправление синхронизирует builder.LJ и TypedOutput до создания запроса |
| Порядок interceptor | Общие параметры заново строят TypedOutput | Восстановление выполняется после добавления общих параметров и перед передачей дальше; копируется уже дополненная форма |
| Неизвестное тело | Может не иметь проверенную структуру form-body | Не переписывается; JSON и multipart не разбираются наугад |
| Повторные поля | Нативный helper добавляет общие параметры, не заменяя старые | Существующий `priority_region` восстанавливается вместе с SIM-полями |
| Ответ | `pack_nil`, `text_type=10`, `status_code=0` | Это поля разобранной модели, не HTTP-статус и не точное объяснение причины |
| Счётчики | `item_count=-1` задан конструктором модели | Не трактуется как число видео; неизвестное значение не заменяется фиктивным успехом |
| UI | Наш код не удаляет карточки поиска и не меняет ответ | Маскировать пустой ответ изменением экрана нельзя |
| Заголовки региона | RegionManager получает их с сервера и хранит отдельно | Не подменяются без знания их семантики; соответствие на устройстве не подтверждено |
| Подпись и авторизация | Используются штатные builder/TypedOutput и цепочка Retrofit | Проверка TLS, авторизация и подпись запросов не отключаются; серверная совместимость требует проверки |
| Кеш | Кешируется чистый исходник и распаковка до патчей | Не содержит обработанных ответов поиска или пользовательского аккаунта |

Тесты покрывают фильтр API, неподходящие хосты, неизменность ленты/логина, обе ветки builder, атомарный отказ несовместимого патча и фактическую reflection-перестройку POST с сохранением кодирования, порядка и повторных полей. Это локальные проверки кода, а не доказательство результатов поиска на телефоне.

Остаточные неизвестные: фактические поля, добавленные позднее нативным TTNet; серверные региональные заголовки; ограничения аккаунта/IP; работа streaming-ответов на конкретной прошивке. Без наблюдения запроса на устройстве нельзя объявить эти причины исключёнными.
